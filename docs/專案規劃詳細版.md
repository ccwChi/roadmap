# Next Roadmap 專案規劃詳細版

## 📋 專案概述

**專案名稱**: Next Roadmap  
**技術棧**: Next.js 16 + React 19 + Zustand + ReactFlow  
**部署方式**: GitHub Pages (靜態導出)  
**核心功能**: 互動式學習路線圖應用，支援離線使用、雲端同步、音樂播放

---

## 🎯 專案目標

打造一個現代化的學習路線圖應用程式，讓使用者能夠：
1. 視覺化瀏覽學習路徑（使用流程圖展示）
2. 追蹤學習進度並記錄筆記
3. 透過 Google Drive 雲端同步資料
4. 支援離線使用（PWA + Service Worker）
5. 邊學習邊聽音樂（Google Drive 音樂播放器）

## 🔧 核心技術實作

### 1. 狀態管理 (Zustand)

#### 主要狀態 Store (`useStore.js`)

**使用技術**:
- 利用 `zustand` 的 `create()` 建立狀態管理器
- 利用 `persist` 中間件進行資料持久化到 localStorage

**持久化資料包含**:
- `user`: 使用者資訊（Google 帳號）
- `isSignedIn`: 登入狀態
- `currentRoadmapId`: 當前選擇的 Roadmap ID
- `progress`: 各 Roadmap 的完成進度 `{ roadmapId: [nodeId1, nodeId2, ...] }`
- `notes`: 各節點的筆記 `{ roadmapId: { nodeId: "content" } }`
- `settings`: 應用設定（主題、自動同步）
- `lastSyncTime`: 最後同步時間
- `pendingSyncCount`: 待同步資料數量

**主要功能函數**:
- `setCurrentRoadmap(id)`: 切換當前 Roadmap
- `toggleNodeComplete(roadmapId, nodeId)`: 切換節點完成狀態，並觸發雲端同步
- `isNodeCompleted(roadmapId, nodeId)`: 檢查節點是否已完成
- `getProgress(roadmapId, totalNodes)`: 計算進度百分比
- `setNote(roadmapId, nodeId, content)`: 儲存筆記並同步
- `syncToCloud()`: 防抖動同步到 Google Drive（500ms 延遲）
- `loadFromCloud()`: 從 Google Drive 載入資料
- `handleOfflineSync(data)`: 處理離線佇列的同步請求

**離線支援機制**:
- 檢測網路狀態（`navigator.onLine`）
- 離線時將資料加入 Background Sync 佇列
- 利用 `offlineSync.js` 的 `queueSync()` 管理待同步資料
- 網路恢復時自動觸發同步

#### 音樂播放器 Store (`useMusicStore.js`)

**使用技術**:
- 同樣使用 `create(persist(...))` 進行狀態管理

**持久化資料包含**:
- `playlist`: 播放清單
- `volume`: 音量設定
- `playMode`: 播放模式（順序、循環、單曲、隨機）
- `hasMusicPermission`: Google Drive 音樂權限狀態

**播放模式**:
- `SEQUENCE`: 順序播放
- `LOOP`: 列表循環
- `SINGLE`: 單曲循環
- `SHUFFLE`: 隨機播放

**主要功能函數**:
- `playTrack(index)`: 播放指定曲目
- `nextTrack()`: 根據播放模式切換下一首
- `prevTrack()`: 切換上一首
- `addToPlaylist(track)`: 新增歌曲到播放清單
- `cyclePlayMode()`: 循環切換播放模式

#### UI 狀態 Store (`useUIStore`)

**非持久化狀態**（不需要儲存）:
- `sidebarOpen`: 側邊欄開關
- `selectedNode`: 當前選中的節點
- `searchQuery`: 搜尋關鍵字
- `settingsOpen`: 設定面板開關
- `isEditingNote`: 筆記編輯模式

### 2. Google Drive 整合

#### 認證與授權 (`googleDrive.js`)

**使用的 Google API**:
- Google API Client (`gapi.client`)
- Google Identity Services (GIS)

**OAuth 2.0 Scopes**:
- `drive.file`: 存取應用程式建立的檔案
- `drive.appdata`: 保留 appdata 權限（未來可切換隱藏資料夾）
- `userinfo.profile`: 讀取使用者個人資料
- `userinfo.email`: 讀取使用者 Email

**初始化流程**:
1. `loadGoogleScripts()`: 動態載入 GAPI 和 GIS 腳本
2. 初始化 `gapi.client` 並載入 Drive API discovery docs
3. 初始化 `tokenClient` 用於 OAuth 2.0 授權

**登入流程**:
1. `signIn()`: 觸發 OAuth 2.0 授權流程
2. 使用 `tokenClient.requestAccessToken()` 請求 token
3. 取得 token 後呼叫 `getUserInfo()` 獲取使用者資訊
4. 延遲 500ms 後呼叫 `loadFromCloud()` 載入雲端資料

**API 就緒檢查**:
- `isGoogleApiReady()`: 檢查 GAPI 是否完全初始化且有 token
- `waitForGoogleApiReady(timeout)`: 等待 API 就緒（輪詢檢查，最多等待指定時間）

#### 資料儲存機制

**資料夾與檔案結構**:
- 資料夾名稱: `AI-Roadmap-Data`（使用者可見）
- 檔案名稱: `roadmap-data.json`
- 儲存位置: Google Drive 根目錄下的專屬資料夾

**資料夾管理**:
- `findOrCreateDataFolder()`: 搜尋或建立資料夾
- 使用快取 `cachedFolderId` 避免重複查詢
- 利用 `gapi.client.drive.files.list()` 搜尋資料夾
- 利用 `gapi.client.drive.files.create()` 建立資料夾

**檔案操作**:
- `findOrCreateDataFile()`: 搜尋或建立 JSON 資料檔案
- `loadData()`: 使用 `files.get()` 讀取檔案內容（`alt: 'media'`）
- `saveData(data)`: 使用 `PATCH` 方法更新檔案內容
- 包含錯誤處理（401/403 權限錯誤、404 檔案不存在）

**資料合併策略**:
- `mergeData(localData, cloudData)`: 比較 `updatedAt` 時間戳
- 使用較新的資料覆蓋舊資料

**備註**: 程式碼中保留了切換到隱藏資料夾（`appDataFolder`）的註解說明，方便未來切換儲存方式。

#### 音樂檔案管理 (`googleDriveMusic.js`)

**音樂資料夾**:
- 預設資料夾名稱: `AI-Roadmap-Music`
- 支援自訂資料夾（使用者可選擇）

**檔案搜尋**:
- `listMusicFiles(folderId)`: 列出指定資料夾中的音樂檔案
- 支援的格式: `.mp3`, `.wav`, `.ogg`, `.m4a`, `.flac`
- 利用 `mimeType` 過濾音訊檔案

**音樂播放**:
- `getMusicFileUrl(fileId)`: 取得音樂檔案的播放 URL
- 使用 Google Drive 的 `webContentLink` 或直接串流
- 處理大檔案的分段載入

**資料夾選擇器**:
- 整合 Google Picker API（如果需要）
- 允許使用者選擇自訂音樂資料夾

### 3. 離線同步機制

#### Service Worker (`worker/index.js`)

**Background Sync 實作**:
- 使用 IndexedDB 儲存待同步資料
- 資料庫名稱: `roadmap-offline-db`
- Object Store: `pending-syncs`

**IndexedDB 操作函數**:
- `openDB()`: 開啟或建立資料庫
- `savePendingSync(data)`: 儲存待同步資料
- `getPendingSyncs()`: 取得所有待同步資料
- `deletePendingSync(id)`: 刪除已同步資料
- `clearPendingSyncs()`: 清空所有待同步資料

**訊息處理**:
- 監聽 `message` 事件處理來自主線程的請求
- `QUEUE_SYNC`: 將資料加入佇列並註冊 Background Sync
- `GET_PENDING_COUNT`: 回傳待同步數量
- `GET_PENDING_DATA`: 回傳所有待同步資料
- `FORCE_SYNC`: 強制執行同步
- `CLEAR_PENDING`: 清空佇列

**Background Sync 事件**:
- 監聽 `sync` 事件（tag: `roadmap-sync`）
- `performSync()`: 執行同步邏輯
- 通知所有 window clients 執行實際的 API 呼叫
- 同步完成後清空佇列

**網路狀態監聽**:
- 監聽 `online` 事件
- 網路恢復時自動註冊 Background Sync

#### 離線同步管理器 (`offlineSync.js`)

**Service Worker 通訊**:
- `sendMessageToSW(message, options)`: 發送訊息給 SW
- 使用 `MessageChannel` 進行雙向通訊
- 包含自動等待和重試機制（最多 2 次重試）
- 超時處理（預設 5 秒）

**降級方案**:
- 當 Service Worker 不可用時使用 localStorage
- `saveToLocalStorage(data)`: 儲存到本地存儲
- `getFromLocalStorage()`: 從本地存儲讀取
- `clearLocalStorage()`: 清空本地存儲

**公開 API**:
- `queueSync(data)`: 將資料加入離線同步佇列
- `getPendingCount()`: 取得待同步數量（SW + localStorage）
- `getPendingData()`: 取得所有待同步資料
- `forceSync()`: 強制同步
- `clearPending()`: 清空待同步佇列

**網路狀態監聽**:
- `listenForNetworkChanges(callback)`: 監聽 online/offline 事件
- `initNetworkStatus()`: 初始化網路狀態管理器

#### 離線同步 Hook (`useOfflineSync.js`)

**功能**:
- 監聽網路狀態變化（online/offline）
- 監聽 Service Worker 訊息（`SYNC_REQUIRED`）
- 監聽頁面可見性變化（`visibilitychange`）
- 監聽頁面關閉前事件（`beforeunload`）

**同步策略**:
- 網路恢復時延遲 1 秒後嘗試同步
- 每 30 秒定期檢查待同步資料
- 頁面變為可見時檢查並同步
- 頁面關閉前觸發立即同步

**防重複同步**:
- 使用 `useRef` 追蹤同步狀態（`isSyncingRef`）
- 避免同時觸發多次同步請求

### 5. PWA 與快取策略

#### PWA 設定 (`next.config.mjs`)

**使用套件**:
- `@ducanh2912/next-pwa`: Next.js PWA 整合

**設定**:
- `dest: 'public'`: Service Worker 輸出目錄
- `disable: process.env.NODE_ENV === 'development'`: 開發環境停用
- `customWorkerSrc: 'worker'`: 自訂 Service Worker 來源
- `reloadOnOnline: true`: 網路恢復時重新載入

**Workbox 快取策略**:

1. **Google Fonts** (CacheFirst):
   - 快取名稱: `google-fonts`
   - 最多 4 個項目
   - 有效期: 1 年

2. **靜態資源** (StaleWhileRevalidate):
   - 快取名稱: `static-resources`
   - 檔案類型: `.js`, `.css`, `.woff2`
   - 最多 32 個項目
   - 有效期: 24 小時

3. **圖片** (CacheFirst):
   - 快取名稱: `images`
   - 檔案類型: `.jpg`, `.png`, `.svg`, `.webp` 等
   - 最多 64 個項目
   - 有效期: 30 天

**預快取資源**:
- `/`: 首頁
- `/manifest.json`: PWA manifest

#### Manifest 設定

**基本資訊**:
- 應用名稱、圖示、主題顏色
- 啟動 URL、顯示模式（standalone）

**圖示**:
- 多種尺寸的 PNG/SVG 圖示
- 支援不同裝置和解析度

##  資料流程

### 使用者操作流程

1. **初次訪問**:
   - 載入應用程式
   - Service Worker 註冊
   - 從 localStorage 載入本地資料
   - 顯示預設 Roadmap

2. **登入 Google**:
   - 點擊登入按鈕
   - OAuth 2.0 授權流程
   - 取得 access token
   - 從 Google Drive 載入雲端資料
   - 合併本地與雲端資料

3. **學習進度追蹤**:
   - 點擊節點查看詳情
   - 標記節點為完成
   - 更新 Zustand store
   - 觸發雲端同步（500ms 防抖動）
   - 如果離線，加入 Background Sync 佇列

4. **筆記記錄**:
   - 在節點詳情中編輯筆記
   - 自動儲存到 Zustand store
   - 觸發雲端同步

5. **離線使用**:
   - 網路斷開時繼續使用
   - 資料變更加入離線佇列
   - 網路恢復時自動同步

6. **音樂播放**:
   - 請求 Google Drive 權限
   - 瀏覽音樂資料夾
   - 新增歌曲到播放清單
   - 播放音樂

### 資料同步流程

**線上同步**:
```
使用者操作 → Zustand store 更新 → syncToCloud() (防抖動 500ms)
→ 檢查網路狀態 → 檢查 Google API 就緒
→ saveData() → Google Drive API → 更新雲端檔案
→ 更新 lastSyncTime
```

**離線同步**:
```
使用者操作 → Zustand store 更新 → syncToCloud()
→ 檢測離線 → queueSync() → Service Worker (IndexedDB)
→ 網路恢復 → Background Sync 觸發
→ Service Worker 通知主線程 → handleOfflineSync()
→ saveData() → Google Drive API
→ clearPending() → 清空佇列
```

## 🔐 安全性考量

### Google API 金鑰

**Client ID**:
- 儲存在環境變數
- 建置時注入到前端程式碼
- 限制授權來源（GitHub Pages domain）

**API Key**:
- 僅用於公開 API（Drive API discovery）
- 限制使用範圍和配額

### 資料隱私

**使用者資料**:
- 儲存在使用者的 Google Drive
- 應用程式無法存取其他使用者的資料
- 使用 OAuth 2.0 授權，使用者可隨時撤銷

**本地資料**:
- 儲存在 localStorage 和 IndexedDB
- 僅在使用者的瀏覽器中
- 清除瀏覽器資料即可刪除
